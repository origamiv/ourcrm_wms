# Роли и права доступа

В администрировании доступны экраны `/main/roles` и `/main/permissions`, источники — существующие `main.roles` и `main.permissions`. Экраны доступны администратору и показывают только записи его `tenant_id`. Доступны создание и редактирование записей. Связи ролей с правами редактируются в отдельной [матрице](ROLES_RIGHTS.md). Назначение ролей пользователям этим экраном не выполняется. Для ролей доступны иконки просмотра, редактирования и удаления. Просмотр открывает карточку без возможности изменения.

Роли: название, код (`slug`), описание, системный признак и статус. Права доступа: название, код, ресурс, системный признак и статус. Доступны поиск, сортировка по названию/коду, фильтры системных и удалённых записей, статуса, страницы по 25 строк. Удалённые записи скрыты по умолчанию.

Синхронизация использует `/web/sync/roles`, `/web/sync/permissions` и соответствующие `/api/sync/roles`, `/api/sync/permissions` с Bearer Token. Контракт описан в [SYNC.md](SYNC.md). Web напрямую вызывает общий серверный сервис. Каждая сущность имеет отдельный браузерный кэш и курсор. Офлайн просмотр доступен в открытом приложении после первой загрузки.

Миграция `000005` устанавливает триггеры на общие таблицы и создаёт начальные события в `public.entity_changes` с классами `App\Models\Role` и `App\Models\Permission`. Она не меняет исходные записи. Последующие INSERT/UPDATE/DELETE/TRUNCATE, включая прямой SQL, поступают через общие функции синхронизации. Откат снимает только эти триггеры, удаляет события этих двух моделей и сбрасывает поколения затронутых тенантов, сохраняя исходные роли и права.

## Создание и редактирование

Нажмите «Добавить роль» / «Добавить право» либо название существующей записи. Общие поля: название, код и статус; для роли также описание, для права — обязательный ресурс. Новая запись получает организацию администратора и `system=false`. Код уникален внутри каталога своей организации, включая удалённые записи. Удалённые записи доступны только для просмотра.

Код `admin` зарезервирован: создавать дополнительные роли с ним или присваивать его другой роли нельзя. У существующей роли `admin` защищён код. Статус ролей, включая системные, выбирается из 1 — Активен и 2 — Отключен. Отключение роли admin запрещено, если оно лишит текущего пользователя административного доступа или роль используется активными назначениями другой организации. У системных прав защищены код, статус и ресурс; название и описание можно редактировать. Поля tenant_id, system, company_id, module_id, feature_id, tags и deleted_at через эти формы не меняются.

Web: `POST /web/roles`, `PUT /web/roles/{id}`, `POST /web/permissions`, `PUT /web/permissions/{id}`. Публичный API: те же маршруты без `/web`, с префиксом `/api` и Bearer Token. Общие обязательные поля: `name`, `slug`, `status` (для ролей — 1 или 2; для прав — 0, 1, 2, 3 либо null); `description` допустимо для роли, `resource` обязательно для права. Обновление требует строковую `version`. Успешное создание — 201, обновление — 200, ответ `{data: запись с version}`; конфликт — 409 с `current`, ошибки полей — 422.

После подтверждения сервером запись обновляется в IndexedDB и других вкладках. При конфликте форма сохраняет ввод и предлагает загрузить актуальную запись; автоматического повторного сохранения нет. Без сети создание и сохранение отключены.

Удаление роли: `DELETE /web/roles/{id}` или `DELETE /api/roles/{id}` с обязательной строковой `version`. Требуется администратор своей организации; системные роли и `admin` защищены (422). Удаление мягкое, через `deleted_at`; запись остаётся доступна в фильтре удалённых. Ответ 200 содержит `{data: запись с version}`, конфликт версии — 409 с `current`. Связи с правами и пользователями сохраняются, удалённая роль исключается из активных ролей и матрицы. В интерфейсе сначала открывается общее окно подтверждения по Figma с именем роли; отмена, крестик и Escape не отправляют запрос.
