# Роли и права доступа

В администрировании доступны экраны `/roles` и `/permissions`, источники — существующие `main.roles` и `main.permissions`. Экраны доступны администратору и показывают только записи его `tenant_id`. Доступны создание и редактирование записей. Связи ролей с правами редактируются в отдельной [матрице](ROLES_RIGHTS.md). Назначение ролей пользователям и удаление записей этим экраном не выполняются.

Роли: название, код (`slug`), описание, системный признак и статус. Права доступа: название, код, ресурс, системный признак и статус. Доступны поиск, сортировка по названию/коду, фильтры системных и удалённых записей, статуса, страницы по 25 строк. Удалённые записи скрыты по умолчанию.

Синхронизация использует `/web/sync/roles`, `/web/sync/permissions` и соответствующие `/api/sync/roles`, `/api/sync/permissions` с Bearer Token. Контракт описан в [SYNC.md](SYNC.md). Web напрямую вызывает общий серверный сервис. Каждая сущность имеет отдельный браузерный кэш и курсор. Офлайн просмотр доступен в открытом приложении после первой загрузки.

Миграция `000005` устанавливает триггеры на общие таблицы и создаёт начальные события в `public.entity_changes` с классами `App\Models\Role` и `App\Models\Permission`. Она не меняет исходные записи. Последующие INSERT/UPDATE/DELETE/TRUNCATE, включая прямой SQL, поступают через общие функции синхронизации. Откат снимает только эти триггеры, удаляет события этих двух моделей и сбрасывает поколения затронутых тенантов, сохраняя исходные роли и права.

## Создание и редактирование

Нажмите «Добавить роль» / «Добавить право» либо название существующей записи. Общие поля: название, код и статус; для роли также описание, для права — обязательный ресурс. Новая запись получает организацию администратора и `system=false`. Код уникален внутри каталога своей организации, включая удалённые записи. Удалённые записи доступны только для просмотра.

Код `admin` зарезервирован: создавать дополнительные роли с ним или присваивать его другой роли нельзя. У существующей роли `admin` защищены код и статус. У системных записей защищены код, статус и ресурс права; название и описание можно редактировать. Поля tenant_id, system, company_id, module_id, feature_id, tags и deleted_at через эти формы не меняются.

Web: `POST /web/roles`, `PUT /web/roles/{id}`, `POST /web/permissions`, `PUT /web/permissions/{id}`. Публичный API: те же маршруты без `/web`, с префиксом `/api` и Bearer Token. Общие обязательные поля: `name`, `slug`, `status` (0, 1, 2, 3 либо null); `description` допустимо для роли, `resource` обязательно для права. Обновление требует строковую `version`. Успешное создание — 201, обновление — 200, ответ `{data: запись с version}`; конфликт — 409 с `current`, ошибки полей — 422.

После подтверждения сервером запись обновляется в IndexedDB и других вкладках. При конфликте форма сохраняет ввод и предлагает загрузить актуальную запись; автоматического повторного сохранения нет. Без сети создание и сохранение отключены.
