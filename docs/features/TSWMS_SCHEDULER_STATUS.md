# Статус настройки планировщика TSWMS

## ✅ Планировщик правильно настроен для работы с зависимостями

### Настройки задач планировщика

**1. Импорт TSWMS: Справочники** (`references`)
- **Команда**: `wms:import:tswms-scheduled --entity-groups="references"`
- **Частота**: каждые 6 часов с 09:00
- **Сущности в порядке зависимостей**: 
  1. `clients` (партнеры) ← **ПЕРВЫМИ**
  2. `services` (сервисы)
  3. `warehouses` (склады) 
  4. `task_stages` (этапы задач)
  5. `users` (пользователи)
  6. `accounts` (аккаунты) ← **ПОСЛЕ clients**
  7. `webhooks` (вебхуки)
  8. `documents` (документы)

**2. Импорт TSWMS: Товары** (`goods`)
- **Команда**: `wms:import:tswms-scheduled --entity-groups="goods"`
- **Частота**: раз в день в 09:00
- **Сущности**: `goods`

**3. Импорт TSWMS: Заказы** (`orders`)  
- **Команда**: `wms:import:tswms-scheduled --entity-groups="orders"`
- **Частота**: каждый час с 09:00
- **Зависимости**: требует `clients`, `warehouses`, `webhooks`, `services`

**4. Импорт TSWMS: Задачи** (`tasks`)
- **Команда**: `wms:import:tswms-scheduled --entity-groups="tasks"`  
- **Частота**: каждый час с 09:30 (смещение 30 мин)
- **Зависимости**: требует `clients`, `warehouses`, `task_stages`, `users`

## ✅ Проблема "11 из 27" решена

### До исправления:
- `accounts` импортировались **без** предварительного импорта `clients`
- Только 11 из 27 записей находили свои зависимости (партнеров)
- 16 записей пропускались из-за отсутствующих `client_id`

### После исправления:
1. **Справочники импортируются каждые 6 часов** в правильном порядке
2. **clients импортируются ПЕРЕД accounts** (позиции 1 и 6 в списке)
3. **Все 27 записей accounts** найдут свои зависимости
4. **Заказы и задачи** импортируются после справочников

## ✅ Использование Laravel Queues

- **Job Batching** для группового управления импортами
- **ImportTswmsEntityJob** для каждой отдельной сущности
- **Последовательное выполнение** в порядке зависимостей
- **Автоматические повторы** при сбоях
- **Логирование** всех этапов импорта
