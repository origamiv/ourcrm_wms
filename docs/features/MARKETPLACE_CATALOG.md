# Каталог маркетплейсов

Команда `integration:sync-catalogs` без tenant-аргумента находит организации со включённой фичей `integration.marketplace_catalog_sync`, их активные аккаунты и связанные активные вебхуки. Для запуска одной площадки используется `--marketplace=wildberries`, `--marketplace=ozon` или `--marketplace=yandex_market`. За один запуск обрабатываются не более 10 вебхуков Wildberries и 100 вебхуков остальных площадок; по умолчанию выбираются вебхуки с самым старым `dat_last_run`. Запуск выполняется синхронно, без очереди. Опция `--tenant` оставлена для ручного ограничения одной организации.

Laravel Scheduler запускает команду отдельно для каждой площадки каждые 30 минут. В текущем окружении планировщик постоянно работает под Supervisor через `php artisan schedule:work` (`wms-scheduler`). Для окружений без Supervisor достаточно добавить в системный cron один вызов планировщика каждую минуту:

```cron
* * * * * cd /var/www/wms.our24.ru && php artisan schedule:run
```

Для включения фичи используется:

```bash
php artisan tenant:feature TENANT_ID integration.marketplace_catalog_sync 1
```

При старте вебхук получает статус `3` (в процессе), после завершения — статус `1`. Статус `3`, сохраняющийся более четырёх часов, автоматически восстанавливается. Сессии запусков хранятся в Redis 30 дней по ключам `marketplace_catalog:account:{account_id}:webhook:{webhook_id}:session:{session_id}`.

До запуска проверяются обязательные реквизиты аккаунта. При отсутствии реквизитов или ответе API 401/403 аккаунт получает статус `2` (заблокирован). Временные сетевые ошибки, ответы 408/425/429 и 5xx повторяются с backoff; аккаунт при таких ошибках не блокируется. Обычная ошибка запуска не меняет активность вебхука: после фиксации ошибки он возвращается в статус `1`. Каталоги загружаются страницами и сохраняются по мере обработки, поэтому частичные данные сохраняются при ошибке, а следующий запуск начинает полный каталог заново.

Для каждой интеграции аккаунт выбирается по `webhooks.params.account_id`. Команда проверяет принадлежность аккаунта tenant и клиенту webhook. Для Яндекс Маркета аккаунт хранит Api-Key в `clients.accounts.token`, а идентификатор бизнеса — в `clients.accounts.src.credentials.business_id`. Каталог загружается методом `businesses/{businessId}/offer-mappings` с постраничным курсором.

Каждый запуск отображается в **Обслуживание → Импорты** с клиентом, marketplace, webhook ID, account ID, текущим статусом, обработанным количеством и текстом ошибки.

Результаты сохраняются в `wms.goods_marketplace`. Для Яндекс Маркета `external_id` и `offer_id` равны `offerId`, а `external_sku` содержит `marketSku`. Сопоставление выполняется по артикулу/offer ID и штрихкоду. Существующее ручное сопоставление не изменяется.

В разделе **Фулфилмент → Каталоги МП** связь с мастер-каталогом можно изменить карандашом в колонке «Мастер-каталог WMS». В поиске отображаются товары и категории; категории выбрать нельзя. После выбора товара нажмите «Сохранить». Ручное сопоставление получает статус `manual`.

Автоматическое создание мастер-товаров выключено по умолчанию. Для включения для организации используется:

```bash
php artisan tenant:feature TENANT_ID integration.auto_create_marketplace_goods 1
```

Для отключения используется значение `0`. При включённой фиче создаются минимальные карточка и товар WMS без категории.
