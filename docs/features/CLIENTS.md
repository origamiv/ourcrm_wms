# Клиенты

Раздел `/clients/clients` открывается через «Клиенты» в левом меню. Его верхняя лента содержит вкладку «Клиенты». Доступ, как у существующих справочников, требует активного администратора.

Источник — существующая таблица `clients.clients`. Модель `App\Models\Client` использует SoftDeletes. Поля карточки: обязательное `name`, необязательное `shortname`, `status` (0 — новый, 1 — активен, 2 — отключен, null — не указан). Строковые поля ограничены 255 символами. `tenant_id` назначает сервер; чтение и изменения ограничены организацией пользователя. Существующие записи с пустым названием показываются по краткому названию или ID.

| Маршрут API | Действие |
| --- | --- |
| `GET /api/sync/clients` | Снимок или дельта общего протокола синхронизации |
| `POST /api/clients` | Создать: `name`, `status`, необязательно `shortname` |
| `PUT /api/clients/{id}` | Изменить: те же поля и строковая `version` |
| `DELETE /api/clients/{id}` | Мягко удалить: строковая `version` |

API требует Bearer Token. Интегрированный интерфейс использует соответствующие `/web/…` маршруты с сессией и CSRF; оба транспорта вызывают `ClientService`. Ответ записи — `{data: {..., version}}`, создание возвращает 201, изменение и удаление — 200. Конфликт версии возвращает 409 с `current`, чужая запись — 404, недопустимые поля — 422.

Миграция `2026_09_10_000008_sync_clients` подключает существующие записи и триггеры к `public.entity_changes`, отдельного журнала не создаёт. Прямые SQL-изменения тоже попадают в синхронизацию. Откат удаляет только инфраструктуру синхронизации клиентов, сохраняя исходные записи. Состояние и ревизии остаются общими в `public.sync_state` с разделением по организации.

Таблица поддерживает поиск по названию и краткому названию, фильтр статуса, сортировку и страницы по 25 записей. Глаз открывает просмотр, карандаш — редактирование, корзина — подтверждение удаления. IndexedDB хранит загруженные данные; при повторном открытии загружается дельта, подтверждённые изменения сразу обновляют кэш. Без сети в открытом приложении доступен просмотр.

Кнопки перехода к документам, доступам, интеграциям, юрлицам и физлицам отключаются и отображаются серыми, если у клиента нет соответствующих неудалённых записей. Сессионный `GET /web/clients/relations?ids[]=...` принимает до 25 ID доступных клиентов и возвращает только логические признаки наличия связей, без содержимого записей и секретов. При ошибке проверки показывается предупреждение; уже известные состояния сохраняются.

В ленте также доступны [«Юр.лица» и «Физ.лица»](CLIENT_PARTIES.md), связанные с клиентами через `client_id`. Клиента с неудалёнными связанными лицами удалить нельзя.
