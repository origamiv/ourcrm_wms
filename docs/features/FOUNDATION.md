# Подготовка основы WMS

## Текущее состояние

Первый этап ограничен документацией: приняты правила разработки и целевая архитектура на основе структуры проекта `../support`, адаптированные для WMS.

В репозитории уже есть Laravel 12, унаследованный прикладной код, каталог `Modules`, базовые классы в `app/OurCRM`, stubs и Swagger. Принятие правил не изменяет их реализацию. Scramble, ClickHouse, полноценное разделение схем PostgreSQL и изоляция организаций должны быть подготовлены отдельными изменениями.

Публичные API, зависимости, конфигурация, stubs и базы данных в документационном этапе не изменяются.

## Последующие работы

1. Разобрать зависимости унаследованного кода чатов, ассистентов и интеграций; удалить прежнюю предметную область из WMS, сохранив полезную общую инфраструктуру и пользовательские правки. Удаление кода не означает удаления данных в БД.
2. Перенести полезную инфраструктуру из существующего `Modules` в стандартные каталоги `app`, обновить ссылки и автозагрузку. Новое дерево доменных модулей не создавать.
3. Адаптировать базовые классы и stubs: модели, контроллеры, миграции и отдельные FormRequest для создания и обновления. Проверить генерацию сущности по правилам WMS.
4. Подключить Scramble, заменить документацию API и удалить Swagger, его конфигурацию, аннотации и артефакты. Проверить генерацию OpenAPI.
5. Подготовить схемы функциональных модулей в одной БД PostgreSQL, миграции и квалифицированные имена таблиц. Реализовать контекст организации и изоляцию через `tenant_id`.
6. Подключить ClickHouse для истории и статистики, определить доставку данных с обработкой повторов и сбоев, добавить DDL и необходимые проверки.

Названия первых складских модулей, конкретные API и контракты доставки истории определяются в соответствующих задачах. Этот список не утверждает их реализацию и не запускает миграции или деплой.
