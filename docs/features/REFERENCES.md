# Справочники

В верхней ленте «Администрирования» кнопка «Справочники» раскрывает обычный вертикальный выпадающий список непосредственно под этой кнопкой. Выбор раздела, клик снаружи или Escape закрывают список; доступны переходы клавишами со стрелками. Доступ к просмотру и изменению требует активного администратора.

| Раздел | Адрес | Источник и область данных |
| --- | --- | --- |
| Модули | `/main/modules` | `main.modules`, общий для всех организаций |
| Возможности | `/main/features` | `main.features`, общий для всех организаций |
| Иконки | `/main/icons` | `main.icons`, своя организация |
| Файлы | `/main/files` | `main.files`, своя организация |

Везде доступны поиск, фильтр статуса, сортировка, страницы по 25 записей, просмотр и редактирование справа, создание и мягкое удаление с подтверждением. Адреса карточек следуют [общим правилам навигации](NAVIGATION.md). Модули и возможности изменяются сразу для всех организаций; `tenant_id` в эти таблицы не добавляется.

## Поля

Общие: обязательное название `name`, статус `status` (0 — новый, 1 — активен, 2 — отключен). Статус может быть null, кроме файлов, где столбец NOT NULL. Существующие пустые названия отображаются по краткому названию или ID.

- Модули: `shortname`, `descr` (до 10000 символов), `fn`, `domain`.
- Возможности: `shortname`, `module_id` (выбор общего модуля), `is_resource` (0/1/null).
- Иконки: `path`, `category`, `size`, `ext`, `company_id`, `user_id`.
- Файлы: поля иконок плюс `is_s3` (0/1/null).

Обычные строки ограничены 255 символами. Размер — неотрицательное целое до 2147483647. Связи с компанией и пользователем доступны только внутри организации. Автор новой иконки или файла по умолчанию — текущий пользователь. Путь, расширение, размер и признак S3 описывают запись файла; этот экран управляет метаданными и не загружает/не удаляет содержимое из файлового хранилища. Пути выводятся как текст.

Модуль нельзя удалить, если он используется в неудалённых возможностях или правах доступа; возможность — если используется в правах. Модель `Feature` имеет связь `module`, модели `Icon` и `File` — `company` и `user`.

## API и синхронизация

`reference` принимает `modules`, `features`, `icons`, `files`:

- `POST /api/{reference}` — создание (201), поля соответствующего раздела.
- `PUT /api/{reference}/{id}` — изменение (200), поля и строковая `version`.
- `DELETE /api/{reference}/{id}` — мягкое удаление (200), строковая `version`.
- `GET /api/sync/{reference}` — снимок/дельта общего протокола.

Bearer Token и роль администратора обязательны. Ответ записи — `{data: {..., version}}`. Конфликт версии — 409 с `current`, недоступная запись — 404, неверные поля/связи или используемая запись — 422. Передавать `tenant_id` запрещено. Интерфейс использует соответствующие `/web/…` маршруты с сессией и CSRF; оба транспорта вызывают `ReferenceService`.

Миграция `2026_09_10_000009_sync_references` подключает существующие записи и прямые SQL-изменения к `public.entity_changes`. Модули/возможности используют общий поток с `tenant_id IS NULL` и соответствующее состояние `public.sync_state`; файлы/иконки — свой tenant. Курсоры привязаны к пользователю и сущности. На клиенте все кэши дополнительно разделены по пользователю и организации. После загрузки сохраняется IndexedDB и запрашиваются дельты; подтверждённые изменения обновляют локальное хранилище. Откат миграции сохраняет исходные таблицы и записи.
