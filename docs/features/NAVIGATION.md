# Адреса разделов и карточек

Адрес списка имеет вид `/{left}/{top}`, карточки — `/{left}/{top}/{id}/{action}`. Первый сегмент соответствует разделу левого меню, второй — вкладке верхней ленты.

| Раздел | Список |
| --- | --- |
| Пользователи | `/main/users` |
| Роли | `/main/roles` |
| Права доступа | `/main/permissions` |
| Роли и права | `/main/roles_rights` |
| Компании | `/main/companies` |
| Контактные лица | `/main/company_contacts` |
| Клиенты | `/clients/clients` |

Действия: `view` — просмотр, `edit` — редактирование, `delete` — окно подтверждения удаления, `password` — установка пароля пользователя. Для создания используется `/0/create`, например `/main/roles/0/create`. У матрицы ролей и прав нет карточки; удаление прав доступа не предусмотрено.

GET-запросы не изменяют записи. Прямые ссылки проверяют доступ администратора и организацию записи. Сохранение и подтверждение удаления используют прежние защищённые `/web/…` маршруты; публичный `/api/…` сохраняет свой контракт.

Карточки отражаются в истории Inertia: работают обновление страницы, прямой переход, кнопки «Назад» и «Вперёд». Открытие карточки в загруженном списке использует IndexedDB и не требует повторной загрузки списка. Прямое открытие сайта после закрытия браузера требует сети.

Фильтр контактных лиц компании сохраняется в query string, в том числе при открытии карточки: `/main/company_contacts/123/edit?company_id=456`. Сервер проверяет принадлежность контакта указанной компании.

Прежние одноуровневые адреса (`/users`, `/roles`, `/clients` и остальные списки) перенаправляют на новые с кодом 301 и сохранением query string.

Подменю «Справочники» в «Администрировании» открывает `/main/modules`, `/main/features`, `/main/icons` и `/main/files`. Карточки используют те же `/{id}/{action}`.

Порядок верхней ленты «Администрирования»: «Пользователи», «Роли», «Компании», «Контактные лица», «Справочники». Выпадающий список «Справочники»: «Права доступа», «Роли и права», «Модули», «Возможности», «Иконки», «Файлы».
