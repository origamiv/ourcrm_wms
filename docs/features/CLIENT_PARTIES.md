# Юридические и физические лица клиентов

В разделе «Клиенты» лента содержит «Клиенты», «Юр.лица» и «Физ.лица». Адреса новых списков — `/clients/companies` и `/clients/individuals`; карточки используют `/{id}/view`, `/{id}/edit`, `/{id}/delete`, создание — `/0/create`.

Источники — существующие `clients.companies` (модель `ClientCompany`) и `clients.individuals` (`ClientIndividual`). Это отдельные сущности от `main.companies` и `main.company_contacts`. Доступ требует активного администратора; чтение, изменения и связи ограничены своей организацией.

Оба раздела поддерживают поиск, фильтр статуса, сортировку, постраничный список, просмотр, создание и редактирование справа, мягкое удаление с подтверждением. `client_id` выбирается из клиентов своей организации и может быть пустым. Клиента с неудалёнными юрлицами или физлицами нельзя удалить до удаления или переноса связанных записей.

## Поля карточек

Юрлица используют ту же карточку и подсказки DaData, что компании в «Администрировании»: обязательные `name`, `shortname`; реквизиты `fullname`, `inn`, `kpp`, `ogrn`, `okpo`, `phone`, `email`, `site`, `director_fio`, `director_position`, `bank`, `bik`, `korr_schet`, `rasch_schet`; статус и клиент. Дополнительные поля `src` — Telegram, ОПФ, юридический адрес, сведения о бухгалтере. Признаки «Наша / Клиент / Партнёр» в этом разделе не показываются и не меняются формой. При сохранении неизвестные ключи `src` сохраняются, но в журнал и браузер не передаются. Служебные `company_src`, `bank_src` и прочие поля исходной таблицы вне карточки не изменяются. Подсказки используют существующий защищённый маршрут `/web/companies/suggestions/{type}` и заполняют форму до сохранения.

Физлица: обязательное отображаемое ФИО `name`; `shortname`, `firstname`, `middlename`, `lastname`, `phone`, `email`, `birthday`; паспортные `passport_seria`, `passport_number`, `passport_date`, `passport_kem`, `passport_code`, `address_reg`; водительское удостоверение `vodud_date`, `vodud_nomer`; `user_id`, `manager_id`, `client_id`, `status`. Пользователь и менеджер выбираются только из своей организации. Даты — `YYYY-MM-DD`, необязательные значения могут быть null. Строки до 255 символов. Статус: 0 — новый, 1 — активен, 2 — отключен, null — не указан.

## API и синхронизация

`party=companies|individuals`:

- `POST /api/clients/{party}` — создание, 201.
- `PUT /api/clients/{party}/{id}` — изменение, 200; обязательна строковая `version`.
- `DELETE /api/clients/{party}/{id}` — мягкое удаление, 200; обязательна строковая `version`.
- `GET /api/sync/client_companies` и `GET /api/sync/client_individuals` — общий протокол снимков и дельт.

API использует Bearer Token. Интерфейс использует `/web/clients/{party}` с сессией и CSRF, общую бизнес-логику `CompanyDirectoryService`. Ответ записи `{data: {..., version}}`; конфликт версии — 409 с `current`, чужая запись — 404, некорректные данные/связь — 422. Передавать `tenant_id` запрещено.

Миграция `2026_09_10_000010_sync_client_parties` подключает таблицы к `public.entity_changes` и состоянию своей организации в `public.sync_state`, включая существующие строки и прямые SQL-изменения. Для JSON используется безопасная проекция, установленная миграцией `000007`. Откат удаляет только подключение к синхронизации и сохраняет исходные записи. В IndexedDB используются независимые типы `client_companies` и `client_individuals`; подтверждённые изменения сразу обновляют кэш, повторные открытия загружают дельту. Без сети в открытом приложении доступен просмотр загруженных данных.

## Открытие из клиента

Иконки «Юрлица» и «Физлица» в колонке «Действия» клиента открывают соответствующий список с `?client_id=ID`. Сервер проверяет клиента своей организации, передаёт `clientScope`; интерфейс показывает только его записи, а поле «Клиент» в карточках заблокировано и предзаполнено. Ограничение сохраняется при поиске, смене статуса, открытии карточки, обновлении страницы и чтении из IndexedDB без сети.

В этом режиме сохранение использует `POST /web/clients/{clientId}/{party}`, `PUT /web/clients/{clientId}/{party}/{id}` и `DELETE /web/clients/{clientId}/{party}/{id}`. Аналогичные `/api/clients/{clientId}/{party}` маршруты доступны с Bearer Token. Сервер сам назначает `client_id` при создании, отклоняет его подмену (422), не находит запись другого клиента (404) и применяет проверку версии. Прямая ссылка на карточку с несовпадающим `client_id` также возвращает 404.

Обычные вкладки «Юр.лица» и «Физ.лица» верхней ленты открывают общий список своей организации без контекста выбранного клиента. Кэш остаётся общим для сущности внутри организации; фильтр не создаёт отдельный журнал или отдельное хранилище.
