# Товары

Левое меню **Товары**, первый пункт ленты **Товары**: `/goods/goods`.
Карточки: `/goods/goods/{id}/{view|edit|delete}`, создание — `/goods/goods/0/create`.
Доступ администраторам; записи изолированы по организации.

Используется существующая `goods.goods`. Поля: id, name, shortname, code,
parent_id, parent_code, type_good, type_unit, barcodes (JSON), articul (JSON),
is_from_external, is_category, status, level, goodcard_id, tenant_id и временные
метки с мягким удалением. В таблице первой отображается колонка `#`; есть код,
краткое название, статус и действия просмотра, редактирования и удаления.
Поиск учитывает название, код и артикулы. Признаки: 1 — Да, 2 — Нет;
статусы: 0 — Новый, 1 — Активен, 2 — Отключен. Уровень вычисляется автоматически:
у корня 0, у ребёнка уровень родителя + 1. Связи родителя не могут образовывать цикл. Запись с дочерними
товарами нельзя удалить.

`articul` — необязательный массив строк, например `["000123", "SKU-001"]`.
Каждый артикул — до 255 символов; ведущие нули сохраняются. В форме артикулы и штрихкоды вводятся списками строк с кнопками добавления и удаления. Количество строк не ограничено интерфейсом; пустые строки при сохранении пропускаются.
`barcodes` редактируется отдельно, структура существующего JSON сохраняется.

## Карточки

Товар — первичная сущность; `goods.good_cards.good_id` ссылается на товар.
У одного товара может быть несколько карточек. `goods.goods.goodcard_id` —
необязательная ссылка на одну основную карточку этого товара. Создание товара
не создаёт карточку автоматически. Форма предлагает только неудалённые
карточки своей организации, принадлежащие редактируемому товару.
Создание и редактирование самих карточек отдельным интерфейсом пока не добавлено.

Миграция 000016 делает goodcard_id nullable, добавляет good_id (bigint FK)
и articul (JSON). Старые значения goodcard_id=0 переводятся в NULL. Обратная
связь восстанавливается для однозначных существующих основных карточек
той же организации; остальные старые карточки остаются без владельца.
Откат структуры блокируется, если он уничтожит связи или нарушит NOT NULL.

## API и синхронизация

- POST `/web/goods/goods`: создать.
- PUT `/web/goods/goods/{id}`: изменить.
- DELETE `/web/goods/goods/{id}`: мягко удалить.
- Bearer API: те же пути с `/api` вместо `/web`.
- Создание/редактирование требуют name, status, level; обновление и удаление —
  строковую version. Устаревшая версия возвращает 409 с актуальной записью.
- Ссылки проверяются на доступность и принадлежность организации. tenant_id
  берётся из авторизованного пользователя, передавать его запрещено.
- Чтение и дельты: `/web/sync/goods`, `/api/sync/goods`.
- Для выбора связей подключена синхронизация good_cards, type_goods, unit_goods
  (соответствующие таблицы схемы goods). Для good_cards доступно только чтение. Из карточек в кеш поступают только id, good_id, name,
  status, tenant_id и временные метки.

Миграция 000017 подключает общий журнал public.entity_changes и счётчики
public.sync_state. Обновления из SQL также фиксируются. Откат синхронизации
сохраняет исходные товары и карточки. Сохранение обновляет IndexedDB сразу;
просмотр ранее загруженного списка работает без связи.

## Справочники товаров

В ленте **Товары → Справочники** открывается обычное выпадающее меню:
**Типы товаров** (`/goods/type_goods`, таблица `goods.type_goods`) и
**Единицы измерения** (`/goods/unit_goods`, таблица `goods.unit_goods`).
Оба раздела поддерживают создание, просмотр, редактирование и мягкое удаление,
поиск по названию/краткому названию и фильтр статуса. Первая колонка — `#`.

Поля: name, shortname, status; tenant_id определяется пользователем.
POST/PUT/DELETE `/web/goods/{type_goods|unit_goods}` (PUT/DELETE с `/{id}`),
Bearer-аналог `/api/goods/...`. Проверяется version; конфликт — 409.
Используемый в товарах тип нельзя удалить, единицу также нельзя удалить,
если она используется в goods.good_cards.unit_id. Изменения справочников
синхронизируются в форму товара через существующие локальные кеши.

## Иерархическое дерево

Таблица товаров строится по parent_id, по образцу дерева базы знаний ../support.
Категории выделены папкой, фоном и полужирным названием; товары — коробкой.
Стрелки раскрывают дочерние строки с отступами. Есть «Развернуть всё» и
«Свернуть всё». Категории идут перед товарами, сортировка по названию действует
внутри каждого уровня. Первая колонка — #, остальные колонки и действия сохранены.

Поиск/фильтры оставляют совпадения вместе с доступными предками и раскрывают
нужные ветки. Пагинация — 25 корневых веток; дети раскрытой ветки остаются на той
же странице. Если родитель недоступен этой организации, доступная дочерняя запись
показывается как корневая, без раскрытия сведений скрытого родителя. Отступ отражает
видимую иерархию; level в БД отражает полную цепочку. Старые некорректные циклы в
офлайн-кэше не приводят к зависанию интерфейса.

level не редактируется вручную; для совместимости API принимает его, но значение не применяется. is_category (1/2) можно изменить у записи без детей. Корневая запись имеет level=0.
is_category=1 при наличии неудалённых детей или включённом ручном признаке категории, иначе 2. Перенос ветки пересчитывает
уровни всех потомков и признаки старого/нового родителей. Удаление последнего
ребёнка снимает автоматический признак категории у родителя, сохраняя ручной выбор; запись с живыми детьми по-прежнему
нельзя удалить через интерфейс/API.

Миграция 000019 устанавливает триггеры goods.goods и выполняет первичный пересчёт.
Вычисления действуют при INSERT/UPDATE/DELETE, включая прямой SQL и мягкое удаление.
Цикл отклоняется с откатом всей операции; отсутствующий/удалённый родитель означает
корневой уровень. Триггеры пересчитывают только изменившиеся level/is_category и
обновляют updated_at; tenant_id, реквизиты и связи не переписываются.
Производные метаданные поддерживаются во всей ветке, включая общие и принадлежащие
разным организациям записи, без расширения доступа к их содержимому.

Изменения товаров сериализуются через общий раздел public.sync_state перед
блокировками организаций, чтобы параллельные переносы не создавали циклов.
Пересчёт выполняется в той же транзакции. Все изменённые строки попадают в обычный
журнал синхронизации; после сохранения карточка применяет ответ и получает дельту
остальных строк. Откат миграции удаляет только её функции, триггеры, индекс и
значение level по умолчанию; товары и рассчитанные значения сохраняются.

## Пустые категории

У записи без неудалённых детей в форме показан переключатель **Является категорией**.
Он сохраняет is_category=1/2. Если дети есть, переключатель скрыт, выключение категории
через API отклоняется с 422. Категория, назначенная вручную, сохраняется при добавлении
и последующем удалении детей. Автоматическая категория без ручного признака после
удаления последнего ребёнка снова становится товаром.

Миграция 000020 добавляет category_manual (внутренний ручной выбор) и has_children
(вычисляемый признак наличия детей). has_children передаётся через журнал и IndexedDB,
поэтому скрытые для организации дети также защищают родителя от выключения категории.
Клиент не изменяет эти служебные поля. Триггеры поддерживают оба признака в одной
транзакции с деревом и публикуют изменения, даже если итоговый is_category не изменился.

## Виды кодов маркировки

Справочник `goods.kind_kiz` (модель `App\Models\KindKiz`) содержит стандартные поля `id`, `name`, `shortname`, `status`, `tenant_id` и временные отметки с мягким удалением. Начальные активные записи: Серийный номер, Честный знак, IMEI, УИН — с NULL tenant_id, без ограничивающих назначений, доступны всем организациям. Общие записи редактирует admin без изменения tenant_id; новые записи принадлежат организации автора. Применяются назначения `main.tenant_entity`.

Страница `/goods/kind_kiz`, карточки `/:id/:action`. Общие GoodCatalogController и отдельные CreateGoodCatalogRequest/UpdateGoodCatalogRequest обслуживают `POST /api/goods/kind_kiz`, `PUT|DELETE /api/goods/kind_kiz/{id}` (Bearer, admin; изменение/удаление с version). Web использует `/web/goods/kind_kiz` и сессию. Дельты `/web/sync/kind_kiz` и `/api/sync/kind_kiz` идут через общий журнал в IndexedDB.
