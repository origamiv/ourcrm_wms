# Документы клиентов

Раздел `/clients/documents` доступен администраторам. Просмотр, создание,
редактирование и мягкое удаление работают через общий сервис для web и API.
Карточки имеют адрес `/clients/documents/{id}/{view|edit|delete}`, создание —
`/clients/documents/0/create`.

`clients.documents`: `id`, `client_id`, `doc_type_id`, `name`, `shortname`,
`status`, `comment` (текст), `internal_comment` (текст), `src` (JSON), `doc_date`,
`accepted_at`, `payed_at`, `canceled_at`, `created_at`, `updated_at`, `deleted_at`,
`tenant_id`. Клиент должен принадлежать организации пользователя. Статусы:
0 — Новый, 1 — Активен, 2 — Отменен, 3 — Отправлен.

`doc_date` принимает `YYYY-MM-DD`; даты подписания, оплаты и отмены —
`YYYY-MM-DDTHH:mm`. Эти поля заполняются вручную, изменение статуса само по себе
не меняет даты. Комментарии необязательны, до 10000 символов каждый. `src`
принимает JSON-объект, массив или null; форма проверяет JSON перед отправкой.
Оба комментария и `src` доступны администраторам и включены в локальный кеш.

`clients.doc_types` — общий справочник с полями `id`, `name`, `shortname`,
`status`, временными метками и мягким удалением. Начальные значения:

| ID | Название |
| --- | --- |
| 1 | Счёт |
| 2 | Акт |
| 3 | УПД |
| 4 | Договор |
| 5 | Дополнительное соглашение |
| 6 | Счёт-фактура |

Меню: Клиенты → Справочники → Типы документов (`/clients/doc_types`).
Справочник допускает добавление и редактирование; статусы 1 — Активен,
2 — Отключен. Используемый тип нельзя удалить. Клиента с неудалёнными
документами также нельзя удалить.

## Транспорт и синхронизация

- `POST /web/clients/{documents|doc_types}` — создание.
- `PUT /web/clients/{documents|doc_types}/{id}` — изменение.
- `DELETE /web/clients/{documents|doc_types}/{id}` — мягкое удаление.
- Bearer API использует те же адреса с `/api` вместо `/web`.
- Для PUT/DELETE обязательна строковая `version`; конфликт возвращает 409
  с актуальной записью. Web защищён сессией и CSRF, API — Sanctum.
- Чтение: `/web/sync/{client_documents|client_doc_types}` (также `/api/sync/...`).
  Общий журнал `public.entity_changes`, состояние `public.sync_state`;
  документы разделены по tenant, типы используют общую NULL-партицию.
- Ответ сохранения сразу обновляет IndexedDB; последующие загрузки получают
  дельту. Изменения прямым SQL также фиксируются триггерами. Bigint-ссылки
  передаются строками, чтобы не терять точность в JavaScript.

Миграция 000011 создаёт обе таблицы и начальные типы, 000012 подключает журнал
и начальный снимок. Откат только 000012 сохраняет документы и типы.

## PDF и настройки печати

Миграция 000013 добавляет в документ `executor_id` (main.companies) и
`customer_id` (clients.companies). Стороны сохраняются в карточке. Исполнитель
должен принадлежать организации и иметь `src.is_own=true` (или 1), Заказчик —
принадлежать организации и клиенту документа. При смене клиента в форме выбор
Заказчика сбрасывается. Ссылки проверяются при сохранении и скачивании.
Удалённые компании недоступны. PDF использует актуальные реквизиты сторон.

Миграция 000014 добавляет `clients.doc_types.settings` типа JSON. Справочник
типов остаётся общим; изменения настроек видны всем организациям и попадают
в IndexedDB. Поле `settings.print` содержит:

```json
{
  "template": "invoice",
  "fields": [
    {"key": "number", "label": "Номер документа", "type": "text", "required": false},
    {"key": "due_date", "label": "Оплатить до", "type": "date", "required": false},
    {"key": "items", "label": "Позиции", "type": "items", "required": true}
  ]
}
```

Доступные типы полей: text, textarea, date, items. Ключи уникальны, латиница,
цифры и подчёркивания. Поле позиций использует ключ `items`. Не более 40 полей.
Форма автоматически строится из настроек выбранного типа; обязательность
проверяется при скачивании, поэтому неполные черновики можно сохранять.

Начальные наборы определены в `config/document_print.php` и записываются в БД:

| Тип / template | Специальные поля |
| --- | --- |
| Счёт / invoice | Основание, срок оплаты, позиции, условия |
| Акт / act | Основание, период, дата оказания услуг, позиции, результат, условия |
| УПД / upd | Основание, дата передачи, грузоотправитель, грузополучатель, основание передачи, позиции, условия |
| Договор / contract | Предмет, срок действия, позиции, условия договора |
| Доп. соглашение / agreement | Номер и дата договора, дата вступления, изменения, позиции, условия |
| Счёт-фактура / vat_invoice | Исправление, платёжный документ, отправитель и получатель, позиции |

У всех типов есть номер. Если номер пуст, в PDF используется ID документа.
Значения хранятся в `documents.src.pdf`, например:

```json
{"pdf":{"number":"42","due_date":"2026-10-01","items":[
  {"name":"Хранение","unit":"сутки","quantity":"2.5","price":"100.00","vat_rate":"20"}
]}}
```

Цена — рубли без НДС, до двух знаков; количество — до трёх. Ставка НДС
задаётся пользователем (0–100, до двух знаков), `none` означает «Без НДС».
НДС начисляется сверху. Суммы рассчитываются целыми копейками с округлением
каждой строки до копейки; максимум 200 позиций, количество до 10000 и цена
до 1000000. Неизвестные поля src не выводятся. `internal_comment` никогда
не печатается; обычный комментарий включается.

`GET /web/clients/documents/{id}/download` и Bearer-аналог
`GET /api/clients/documents/{id}/download` возвращают `application/pdf` с
`Content-Disposition: attachment`, имя `document_{id}.pdf`. Файл генерируется
Dompdf в памяти, без сохранения в публичный каталог; удалённые или чужие
документы недоступны, статус не меняется. Ошибки данных возвращают 422.

Шаблоны — HTML-печатные представления с реквизитами, таблицами сумм и текстом
из настроенных полей. Условия договоров заполняются пользователем; система
не сочиняет обязательства и не проставляет подписи. Формы не являются
форматом электронного УПД/счёта-фактуры для обмена с ФНС.

## Ручная сумма и региональный формат

Миграция 000015 добавляет `clients.documents.amount` (`numeric(18,2)`,
nullable). Это ручная сумма, которая не пересчитывается из `src.pdf.items`.
API принимает неотрицательную десятичную строку с максимум двумя знаками
после точки; журнал и IndexedDB возвращают строку без потери точности.
Сумма доступна в карточке и отдельной колонке списка. Расчёт итогов позиций
в печатной форме сохраняет прежнюю независимую логику.

В интерфейсе и PDF даты отображаются как `дд.мм.гг`, время — `чч:мм`
(24 часа). Общий `RussianDateInput` задаёт русские месяцы и неделю Пн–Вс
независимо от языка браузера, включая мобильный календарь. В хранилищах
и API остаются ISO-даты с полным годом, без изменения часового пояса.
При ручном вводе можно указать четырёхзначный год. Для нового значения с
двузначным годом 00–49 означают 2000–2049, 50–99 — 1950–1999; если
двузначный год совпадает с сохранённым, его век сохраняется.
