# Документы клиентов

Раздел `/clients/documents` доступен администраторам. Просмотр, создание,
редактирование и мягкое удаление работают через общий сервис для web и API.
Карточки имеют адрес `/clients/documents/{id}/{view|edit|delete}`, создание —
`/clients/documents/0/create`.

`clients.documents`: `id`, `client_id`, `doc_type_id`, `name`, `shortname`,
`status`, `comment` (текст), `internal_comment` (текст), `src` (JSON), `doc_date`,
`accepted_at`, `payed_at`, `canceled_at`, `created_at`, `updated_at`, `deleted_at`,
`tenant_id`. Клиент должен принадлежать организации пользователя. Статусы:
0 — Новый, 1 — Активен, 2 — Отменен, 3 — Отправлен.

`doc_date` принимает `YYYY-MM-DD`; даты подписания, оплаты и отмены —
`YYYY-MM-DDTHH:mm`. Эти поля заполняются вручную, изменение статуса само по себе
не меняет даты. Комментарии необязательны, до 10000 символов каждый. `src`
принимает JSON-объект, массив или null; форма проверяет JSON перед отправкой.
Оба комментария и `src` доступны администраторам и включены в локальный кеш.

`clients.doc_types` — общий справочник с полями `id`, `name`, `shortname`,
`status`, временными метками и мягким удалением. Начальные значения:

| ID | Название |
| --- | --- |
| 1 | Счёт |
| 2 | Акт |
| 3 | УПД |
| 4 | Договор |
| 5 | Дополнительное соглашение |
| 6 | Счёт-фактура |

Меню: Клиенты → Справочники → Типы документов (`/clients/doc_types`).
Справочник допускает добавление и редактирование; статусы 1 — Активен,
2 — Отключен. Используемый тип нельзя удалить. Клиента с неудалёнными
документами также нельзя удалить.

## Транспорт и синхронизация

- `POST /web/clients/{documents|doc_types}` — создание.
- `PUT /web/clients/{documents|doc_types}/{id}` — изменение.
- `DELETE /web/clients/{documents|doc_types}/{id}` — мягкое удаление.
- Bearer API использует те же адреса с `/api` вместо `/web`.
- Для PUT/DELETE обязательна строковая `version`; конфликт возвращает 409
  с актуальной записью. Web защищён сессией и CSRF, API — Sanctum.
- Чтение: `/web/sync/{client_documents|client_doc_types}` (также `/api/sync/...`).
  Общий журнал `public.entity_changes`, состояние `public.sync_state`;
  документы разделены по tenant, типы используют общую NULL-партицию.
- Ответ сохранения сразу обновляет IndexedDB; последующие загрузки получают
  дельту. Изменения прямым SQL также фиксируются триггерами. Bigint-ссылки
  передаются строками, чтобы не терять точность в JavaScript.

Миграция 000011 создаёт обе таблицы и начальные типы, 000012 подключает журнал
и начальный снимок. Откат только 000012 сохраняет документы и типы.
