# Правила изменения проекта

- Менять файлы, непосредственно связанные с задачей, включая необходимые тесты, миграции и документацию.
- Не откатывать, не перезаписывать и не коммитить посторонние пользовательские изменения.
- Не выполнять массовое форматирование, переименование или удаление вне задачи.
- Секреты, `.env`, приватные ключи, дампы и реальные пользовательские данные не включать в репозиторий.
- Очистка унаследованной предметной области — отдельная работа из [плана основы](../features/FOUNDATION.md); принятие документации само по себе не означает удаления кода или данных.

## Git

- Работать в текущей ветке, если задача не предусматривает другую.
- Перед работой проверить статус и выполнить `git pull --ff-only`, сохраняя пользовательские правки.
- После проверок каждой завершённой задачи сделать коммит и push в текущую ветку, включая `master`; обязательного PR правила проекта не требуют.
- Автор: Вениамин Смородинский <origamiv@gmail.com>. Сообщение — на русском языке, без упоминания соавторства агента.
- Проверять staged diff и добавлять файлы адресно. Не применять force push и не переписывать историю без отдельного основания.
- Неудача обновления или push не разрешает потерю локальных изменений; причину сообщить в отчёте.

## Документация и окружение

- Общая навигация — в `README.md`, процесс — в `WORKFLOW.md`, правила — в `docs/rights`.
- API и технические возможности — в `docs/features`, пользовательские сценарии — в `docs/help`.
- Не переносить адреса серверов, credentials, команды деплоя и предметные ограничения исходного проекта. Эти правила не устанавливают автоматический деплой WMS.

Общие записи с tenant_id IS NULL подчиняются [правилу main.tenant_entity](../features/TENANT_VISIBILITY.md). Редактирование разрешено только admin при наличии видимости; tenant_id сохраняется без изменений. При проверке полномочий учитываются доступность назначения role_user и активность назначенной роли. Видимость записи роли в справочнике не отменяет её явное назначение пользователю.
