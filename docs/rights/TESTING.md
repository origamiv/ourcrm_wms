# Проверки WMS

## Выбор проверок

- Backend-логика, модели, сервисы, jobs и миграции: относящиеся к изменению тесты через `php artisan test` или `vendor/bin/pest`.
- Форматирование PHP: `vendor/bin/pint --test` для затронутых файлов.
- Изменения frontend и конфигурации сборки: `npm run build`.
- Только документация: проверить относительные ссылки, согласованность правил, границы изменений и `git diff --check`. Тесты приложения и миграции не требуются.
- Перед коммитом проверить `git status --short`, staged diff и `git diff --cached --check`.

## Сценарии при реализации основы

- Для сущностей проверять валидацию создания и обновления, авторизацию, SoftDeletes и lookup-связи.
- Для мультитенантности проверять запрет чтения и изменения данных другой организации, подмены `tenant_id` и связывания с чужими записями; учитывать jobs, экспорт и статистику.
- Для PostgreSQL проверять миграции и межсхемные связи в отдельной тестовой БД PostgreSQL: SQLite не подтверждает работу схем PostgreSQL.
- Для ClickHouse проверять запись и чтение истории, границы организаций, повторную доставку и недоступность хранилища согласно реализуемому контракту.
- Для Scramble проверять генерацию OpenAPI, маршруты, описание Bearer-аутентификации и соответствие документации фактическому API.
- Для stubs проверять, что сгенерированная сущность использует правильные базовые классы, раздельные FormRequest и стандартные каталоги Laravel.

## Окружение и отчёт

Не выполнять разрушающие проверки на рабочей БД. Проверять фактические команды и зависимости перед запуском; не считать запланированную инфраструктуру установленной.

В отчёте указывать выполненные проверки и результат. Если нужная проверка недоступна, сообщать причину и ограничение результата.

## Проверки каркаса пользователей

PHP-тесты используют только локальную PostgreSQL через Unix socket `/var/run/postgresql`, базу `wms_test` и роль `root`; эти значения закреплены в `phpunit.xml`. Фикстуры создаются внутри откатываемой транзакции. Браузерные тесты используют отдельную `wms_browser_test`, сами подготавливают фикстуры и запускают сервер на `127.0.0.1:8137`. Проверка параллельных записей использует `wms_concurrency_test` и удаляет только собственные тестовые схемы в этой базе. Никакие тесты не запускаются на БД из рабочего `.env`.

Для тестового окружения заранее создать эти три локальные БД с владельцем `root` и установить Chromium: `npx playwright install --with-deps chromium`.

```shell
vendor/bin/pest
php tests/Support/concurrency.php
npm run test:cache
npm run typecheck
npm run build
npm run test:browser
```

Браузерные учётные записи из `tests/Support/prepare_browser.php` являются синтетическими и существуют только в тестовой БД. `composer test` не определён.
