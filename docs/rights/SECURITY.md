# Безопасность WMS

## Секреты

- Получать credentials из конфигурации и окружения. Примеры переменных документировать без реальных значений.
- Не выводить секреты и персональные данные в логи, ответы API, тестовые фикстуры и отчёты.

## Доступ и мультитенантность

- API по умолчанию защищать `auth:sanctum`. Аутентификация не заменяет проверку прав и принадлежности данных организации.
- Не доверять `tenant_id` из запроса: организация должна подтверждаться авторизованным контекстом и правами пользователя.
- Ограничивать организацией списки, получение по ID, создание, обновление, удаление и восстановление бизнес-сущностей.
- Lookup-ID проверять на принадлежность доступной организации, включая soft-deleted записи, если операция допускает их использование.
- Фоновые задания, экспорт, история и статистика также должны соблюдать границы организаций. Не допускать утечки контекста между заданиями.
- Валидацию входных данных выполнять через FormRequest. Не разрешать массовое присвоение служебных полей без проверки.

## Базы данных и интеграции

- Параметризовать значения SQL для PostgreSQL и ClickHouse. Имена схем, таблиц и полей не формировать из непроверенного пользовательского ввода.
- Для внешних HTTP-клиентов задавать timeout и обрабатывать ошибки без раскрытия секретов.
- Фоновые операции проектировать с учётом повторного выполнения; не применять одну бизнес-операцию повторно из-за retry.
- Миграции и тесты выполнять в предназначенном для задачи окружении. Не использовать рабочую БД для разрушающих тестов.
