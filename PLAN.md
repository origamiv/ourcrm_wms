# Раздел «Обслуживание → Фоновые процессы»

## Кратко

Добавить администраторский экран `/maintenance/background_processes` с группировками «По клиентам» и «По вебхукам», фильтрами периода и агрегатами запусков из `wms.import_runs`, связанных с `integration.webhooks`.

## Изменения

- Добавить вкладку «Фоновые процессы» в раздел «Обслуживание», Inertia-страницу и регистрацию компонента.
- Создать внутренний GET API `/web/background_processes` с параметрами:
  - `group_by`: `clients` или `webhooks`;
  - `period`: `today`, `yesterday`, `week`, `month`, `hours_4`, `hour`, `minutes_15`;
  - `page`: положительное целое, по 50 строк.
- Сервис статистики должен:
  - применять `visibleTo($tenant)` и учитывать только неудалённые вебхуки со статусами `1` и временным `3`;
  - в группировке по клиентам исключать вебхуки без `client_id`;
  - считать по выбранному периоду `total_runs`, `successful_runs`, `failed_runs`, `running_runs` и `without_runs`;
  - относить `completed` к успешным, `failed` — к неуспешным, а `queued` и `running` — к выполняющимся;
  - включать все перечисленные статусы в «Всего запусков»;
  - считать `without_runs` как число вебхуков, не имеющих запусков в выбранном периоде; для строки вебхука возвращать `1` или `0`;
  - сортировать строки по названию, затем по ID.
- Временные границы рассчитывать в `Europe/Moscow`:
  - сегодня, вчера, текущая неделя Пн–Вс и текущий месяц — календарные окна;
  - 4 часа, час и 15 минут — скользящие окна до текущего момента;
  - числовые колонки относятся только к выбранному окну;
  - статистика охватывает выбранное и два предыдущих однотипных окна;
  - месяц и неделя разбиваются по дням, сегодня/вчера — по часам, часовые фильтры — по минутам.
- Ответ API должен содержать границы выбранного и полного статистического диапазона, единицу квадратов, пагинацию и строки с `id`, `name`, пятью счётчиками и разреженным массивом непустых интервалов активности.
- Таблица:
  - первая колонка `#`, затем «Клиент» или «Вебхук»;
  - далее «Всего запусков», «Успешных», «Неуспешных», «Выполняются», «Без запусков», «Статистика»;
  - над таблицей разместить переключатели группировки и периода;
  - статистику отображать сеткой квадратов: пустой интервал серый, активные интервалы имеют четыре уровня зелёной насыщенности относительно максимума строки;
  - подсказка квадрата показывает интервал и точное число запусков;
  - на мобильном строки превращаются в раскрываемые карточки, сетка статистики прокручивается внутри карточки без горизонтальной прокрутки всей страницы.
- Перезагружать данные при смене группировки, периода и страницы. Автообновление и переходы по строкам или квадратам в первой версии не добавлять.
- Добавить составной индекс `wms.import_runs (tenant_id, source_webhook_id, created_at)` отдельной миграцией; новых таблиц не создавать.
- Описать экран и правила расчёта в технической документации и пользовательской справке.

## Проверки

- Feature-тесты API: права администратора, изоляция tenant, видимость вебхуков, исключение удалённых, отключённых и записей без клиента, группировки и пагинация.
- Проверить все семь периодов, московские границы, переход месяца и недели, три последовательных окна и минутные, часовые и дневные интервалы.
- Проверить распределение `completed`, `failed`, `queued`, `running`, общий счётчик и расчёт «Без запусков».
- Проверить переключатели, загрузку, ошибки, пустое состояние, первую колонку `#`, квадраты активности и мобильное отображение.
- Перед завершением применить миграцию через `php artisan migrate --force`, выполнить профильные тесты, `vendor/bin/pint --test`, `npm run build`, `php artisan optimize:clear`, `git diff --check`.
- Сделать один коммит с русским сообщением от Вениамина Смородинского и push в текущую ветку без включения посторонних изменений.

## Допущения

- По умолчанию выбраны «По клиентам» и «Сегодня».
- Запуск связывается с вебхуком только через `wms.import_runs.source_webhook_id`; поля `cnt` и `dat_last_run` не используются как история.
- Колонка «Выполняются» объединяет статусы `queued` и `running`.
- Миграции данных и новый публичный Bearer API не требуются.
