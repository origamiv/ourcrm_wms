# План: общий поиск в таблицах

## Цель

Добавить на все экраны, где уже доступен конструктор фильтров, единый поиск по данным таблицы. Иконка поиска располагается перед иконкой фильтра, раскрывается в компактный инпут и поддерживает два режима: фильтрацию строк и навигацию по найденным строкам без изменения состава таблицы.

## Интерфейс

1. Добавить общий Vue-компонент поиска рядом с `FilterPresetButton` на всех соответствующих экранах.
2. При нажатии на иконку раскрывать инпут; пустой инпут сворачивать при `Escape` или после ухода фокуса со всего блока.
3. Непустой инпут оставлять раскрытым в текущем состоянии компонента.
4. Запускать поиск после ввода трёх символов с debounce 300 мс; для одного-двух символов показывать подсказку без изменения таблицы.
5. Внутри блока поиска разместить кнопку выбора полей, переключатель режима, счётчик совпадений и стрелки навигации.
6. По умолчанию выбирать доступные поля `name`, `shortname`, `id`; запрещать снятие последнего выбранного поля.
7. Сохранять выбранные поля в `localStorage` отдельно по пользователю, организации и экрану. Строку поиска и режим не сохранять; режим по умолчанию — «С фильтром».
8. На мобильных экранах обеспечить компактное размещение с переносом элементов без горизонтальной прокрутки страницы.

## Логика поиска

1. Выполнять регистронезависимый поиск по подстроке.
2. Между выбранными полями использовать `OR`, с быстрыми и сохранёнными фильтрами — `AND`.
3. Искать как по исходным, так и по отображаемым значениям, включая русские подписи статусов, вложенные поля и массивы.
4. В режиме «С фильтром» ограничивать строки и экспорт результатами поиска, сбрасывая пагинацию при изменении параметров.
5. В режиме «Без фильтра» не менять таблицу, экспорт и агрегаты; подсвечивать совпадения, выделять текущее и переходить по ним без зацикливания.
6. Поддержать переходы кнопками и клавишами `Enter` / `Shift+Enter`, автоматическую смену страницы и прокрутку к найденной строке.

## Серверные таблицы

1. Поддержать параметры `search`, `search_fields[]`, `search_mode` и `search_index` в серверных списках импортов, фоновых процессов и журнала запусков интеграций.
2. Для каждого endpoint использовать явный список разрешённых полей и безопасные SQL-выражения.
3. В режиме фильтра применять поиск до пагинации и до расчёта календаря/агрегаций.
4. В режиме подсветки не менять основной набор данных и возвращать метаданные навигации: число совпадений, индекс, идентификатор и страницу целевой строки.
5. Для календаря запусков выполнять навигацию только по запускам выбранного квадрата/дня, не меняя сам календарь.

## Реализация

1. Создать общую библиотеку поиска и компонент интерфейса.
2. Подключить их на экраны пользователей, клиентов, справочников, товаров маркетплейсов, инструкций, ролей и прав, рабочего времени, импортов, фоновых процессов и журнала запусков интеграций.
3. Сохранить существующие локальные поиски по отдельным колонкам.
4. Добавить серверный сервис безопасного поиска и подключить его к серверным endpoint.
5. Добавить стили подсветки, доступные подписи и управление с клавиатуры.
6. Описать пользовательский сценарий в документации.
