# HTTPS-доступ WMS к DaData

На рабочем сервере `wms-normal-egress` маркирует трафик `www-data` значением `0x1bd00`, исключая его из маршрута NetBird. Прямой маршрут к `suggestions.dadata.ru:443` недоступен: PHP-FPM получает таймаут подключения, хотя CLI под root работает через NetBird.

`wms-dadata-egress` ставит перед общей маркировкой узкое исключение: только пользователь `www-data`, TCP/443 и текущие IPv4-адреса `suggestions.dadata.ru`. Остальные направления используют прежние правила. Скрипт не меняет маршруты и не содержит ключей DaData.

Файлы установлены на рабочем сервере:

- `wms-dadata-egress` → `/usr/local/sbin/wms-dadata-egress`, режим 0755;
- service и timer → `/etc/systemd/system/`, режим 0644;
- `wms-dadata-egress.timer` включён, обновляет DNS-набор через 10 секунд после загрузки и каждые 5 минут.

Зависимости — Python 3 и iptables. Повторный запуск не дублирует правила. Скрипт изменяет только правила со своим комментарием `wms-dadata-https`, удаляет устаревшие адреса и восстанавливает положение перед общей маркировкой. При ошибке DNS сохраняются предыдущие правила. Одновременные запуски исключены файловой блокировкой.

Проверка: `systemctl status wms-dadata-egress.timer`, `journalctl -u wms-dadata-egress.service`, `iptables -t mangle -S OUTPUT`. Проверять интеграцию нужно также через PHP-FPM, а не только через `php artisan`: сетевые маршруты зависят от пользователя процесса. Проверены реальные ответы party и bank через веб-процесс после установки исключения.

Для отката отключите таймер и удалите только правила с комментарием `wms-dadata-https`. Существующее правило `wms-normal-egress` сохраняется.
